# 礼拜时间算法

InkSalah 在设备上直接计算礼拜时间边界，不下载城市时刻表。计算结果由以下内容共同决定：

1. 公历日期；
2. 经纬度；
3. 固定 UTC 偏移；
4. 所选晨昏计算规则；
5. Standard 或 Hanafi Asr 影长规则；
6. 七个时间各自的分钟微调。

## 时间边界与窗口

| 时间边界 | 在 InkSalah 中的含义 | 在此结束的窗口 |
| --- | --- | --- |
| Fajr | 所选机构规则定义的晨光边界 | 前一晚 Isha |
| Sunrise | 太阳中心约 −0.833°，包含常用大气折射修正 | Fajr |
| Dhuhr | 当地太阳正午 | 两次礼拜之间的白天时段 |
| Asr | 下午影长达到所选教法规则 | Dhuhr |
| Maghrib | 日落或机构定义的 Maghrib 边界 | Asr |
| Isha | 暮光角度，或 Maghrib 后固定分钟数 | Maghrib |
| Qiyam | 夜晚最后三分之一开始 | 作为与 Isha 重叠的自愿礼拜时段显示 |

Isha 会持续到次日 Fajr。开启 Qiyam 显示后，它是额外的夜间标记，不会替代或缩短 Isha。

## Asr 教法规则

- `STANDARD`：影长系数为 1，对应 Shafi、Maliki 和 Hanbali 的常用规则。
- `HANAFI`：影长系数为 2，Asr 开始时间会更晚。

Asr 教法选项只改变 Asr，不影响其他时间。

## Qiyam

Qiyam 表示夜晚最后三分之一的开始：

```text
夜长 = 次日 Fajr - 当日 Maghrib
Qiyam = 当日 Maghrib + 2/3 × 夜长
```

因为这里必须使用次日 Fajr，固件会把相邻日期一起计算。

## 高纬度处理

对采用角度的计算规则，如果指定晨昏角度没有实际发生，或者结果超出合理夜长，InkSalah 会按角度占夜长的比例限制 Fajr 和 Isha。`MOONSIGHTING` 使用随纬度和季节变化的晨间与晚间安全区间，在极高纬度采用七分之一夜长规则。

这些规则用于保证设备能得到稳定的数学结果；当地宗教机构可能采用另一套高纬度约定。用户可以用七项独立分钟微调与可信的当地时刻表对齐。

## 精度与已知限制

- 时间四舍五入到分钟。
- Dhuhr 当前使用当地太阳正午，没有自动增加 zawal 后等待时间。
- 时区保存为固定 UTC 偏移，不含 IANA 时区数据库；夏令时变化后需要重新核对。
- 公网 IP 定位只能估算地点，需要在设备上确认。
- 大气和当地地平线环境可能影响实际观察到的日出日落。

参加集体礼拜时，请以当地清真寺公布的时刻表和 iqamah 安排为实际依据。
